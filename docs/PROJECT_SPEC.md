# 项目实现说明

更新：2026-10-22。当前执行规则以本文件与根目录 `AGENTS.md` 为准；旧版固定进房比例、单轮必关页和固定风险冷却已移除。

## 架构

| 模块 | 职责 |
| --- | --- |
| shared/config、policy、config-validation | 单一配置/数据类型、初值、范围校验 |
| runtime-repository | 账号隔离、明细、原子预留、冷却、统计及风险记录 |
| runtime | electron-store 持久化、迁移备份、全局执行入口 |
| execution-gate | 串行副作用队列、AbortSignal 与代次取消 |
| session-engine | 工作/收尾/休息/恢复、每日时长、时区和时钟检查 |
| browser-manager | 共享 Context、托管页面、统一导航、停止关页 |
| passive-observer、lottery-parser | 自然响应及 JSON 提示、任务、服务器时钟、风险信号 |
| lottery-dom | 可见入口、弹窗范围、明确任务按钮、DOM MutationObserver |
| discovery-service | 入口链接发现、逐个观察验证、保留页面接管 |
| strategy | 可行性、任务提前量、机会估算、完整占用区间组合、历史排序 |
| auto-runner | 扫描、历史复访、候选、正式参与的编排，支持可注入环境回归 |
| room-manager、fudai-service | 页面生命周期与每轮任务、支付确认、开奖收尾、有限续留 |
| stats-service | 从轮次账本派生统计，不重复累计回调 |
| IPC / preload / Vue | 严格可写字段白名单、状态推送、设置、记录与脱敏导出 |

旧 `min-interval-queue.ts` 和基于二进制转文本的 `ws-analyzer.ts` 已被统一队列与被动观测替代。

Vue 界面现按运行面板、策略设置、房间库、运行记录、运行日志组织；实现分别位于 `RunDashboard.vue`、`SettingsView.vue`、`RecordsView.vue`、`ActivityLog.vue`，由 `App.vue` 管理导航。设置草稿跨视图保留，统一校验和保存；`useIpc.ts` 统一操作等待、错误反馈和主进程确认，未确认停止前不会提前显示停止成功。详细界面验收见 [UI_REDESIGN.md](UI_REDESIGN.md)。

## 数据与可信边界

`config.json` 保留基础设置及旧汇总；`runtime-v2.json` 以账号 UID Cookie 哈希为作用域保存房间、观测、轮次、支付、风险、决策与会话。`auth.json` 仅用于浏览器登录复用，不进入导出。首次升级有独立备份；重复绑定账号不会重复迁移旧额度。

轮次键是规范化直播间 URL + lotteryId。页面关闭或无明确开奖结果记 unknown；重复确认、晚到中奖及金额补全更新同一记录。首次确认耗时固定，避免开奖等待被错误学习为任务耗时。

只解析当前页面自然响应中的明确 `lottery_info` 结构；福袋名额、参与人数、钻石总额与单人奖励使用独立字段。未知为 null，在线人数不映射为参与人数。成本可以由当前可见弹窗的明确价格补全。WebSocket JSON 只提供提示，二进制消息不提供倒计时或资格。

主候选需身份、已知任务、可靠开奖时间和可行成本。网络响应使用服务器偏移校准绝对 drawAt；网络缺少时间但存在可信可见 ShortTouch 时可补时间。只有 DOM 时间但缺少任务/身份则复验，不能据页面文本猜任务。正式结果要求当前弹窗 `/webcast/lottery/right/` 身份一致，避免旧结果污染新轮。

## 预算

支付状态：reserved → submitted → confirmed / failed / unresolved。未知结果继续占用额度并阻断后续启动；手动核对只允许处理 unresolved。

同轮支付键固定，原子检查与预留在主进程同步提交，避免两个请求同时消耗最后额度。重复业务响应不能重复入账。原始单位不明确或只显示抖币数量，不换算成已获钻石。

预算同时受总量、每日、单主播累计、单次费用、每日新团和奖励再投入比例/上限控制。免费资格跳过费用限制。明确历史会员重新点亮不增加新团数；身份不明保守计入新团数量。重置显示统计不改变预算或奖励本金。

## 选择与时间

验证导航串行，进入后观察 22–28 秒，无无意义随机滚动。正常失败首次冷却 30 分钟，连续失败指数退避，最多 240 分钟；有机会但字段不足也低频复验。历史来源不要求再次出现在入口页。

`evaluate` 先排除类型、分享/未知任务、费用、时间不够等情况。名额 K 与参与人数 N 可得时，在等资格等概率假设下估算 p=K/N；足够同轮样本时使用非负增长率估计开奖人数。有效参与率 q 的样本不足时使用保守启发初值，界面不会称其为平台抽奖权重。

机会目标按 q×p/T；钻石目标按 (q×p×平均单人钻石−新增成本)/T。未知竞争度使用资格可完成性和时间，不与已量化概率混作同一分数。组合调度枚举最多 6 个待裁剪候选，结果最多保留 5 个，最大化兼容区间总效用。

进房提前量包括导航最大等待、加载、评论/关注/付款、已知看播等待和确认余量，配置提前秒数是下限。当前页面接管不重复计算导航等待。已经确认参与的本轮优先收尾。

同房每轮开奖后观察最多 25 秒，随后结算并决定续留。仅新身份触发新任务；最多 3 轮、20 分钟驻留、等待下一袋最多 60 秒（均可配置）。当前轮次由一个服务状态机管理，没有互相竞争的开奖关页定时器。

## 运行与取消

SessionEngine 保存实际随机时段与恢复时间，每个阶段只生成一次。允许时段结束、每日额度、用户定时停止和单段长度共同决定硬截止；提前 90 秒开始收尾。计划恢复重新校验账号、预算未决、风险和时段。

全局导航及按钮、键盘操作进入 ExecutionGate，等待前后校验信号与状态。所有入口共用每小时导航/新房数、每分钟动作数和每日活跃限额。停止先同步中止信号，再关闭页面、清理监听并等待在途任务结束；迟到的启动/恢复检查受运行修订号拦截。

明确验证挑战、95152、429 或支付限制保存风险记录并阻断所有工作页面。普通网络失败仅走冷却；聊天中出现相关词语不单独判为风险。应用重启不自动恢复；活跃时长大幅跳变或单调时钟与系统时钟不一致时停止，不补做过期任务。

## 验证与局限

纯逻辑、真实浏览器离线夹具、调度器与 Electron 冒烟覆盖主要边界。日常验收只执行必要的测试、类型检查和代码编译，默认不生成安装包；Windows 打包仅在用户明确要求发行产物时执行。历史构建及 Windows 包检查见 `DELIVERY.md`，不构成每次修改的必做项。线上页面变动、账号差异和未公开协议仍需用户实际观察后提供脱敏样本；离线通过不表示已证明中奖率提高或不会触发平台限制。

高级学习、预测校准、自适应 bandit、按活动类型兑奖提醒仍属原清单 M8 可选范围；已有历史平滑、简单增长和耗时分位初值不等于完成这些实验。
