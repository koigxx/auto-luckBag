# 使用说明

## 登录和启动

开发运行 `npm run dev`，安装版直接打开应用。点击“登录抖音”，在弹出的浏览器中完成登录。程序同时检查登录 Cookie、稳定 UID 标识和本人登录界面，不能确认时不会分配账号账本。退出登录会先停止工作页面。

在左侧“策略设置”选择福袋类型、基础钻石预算和运行节奏，统一点击“保存设置”。未保存的草稿跨页面保留，开始运行前必须保存或还原。保存失败时草稿不会丢失，按提示修改后重试。

回到“运行面板”，点击“开始运行”。“本次运行选项”可选择首页、关注页或分类页作为发现入口，并设置本次定时停止。主按钮随状态切换为登录、开始、停止或查看待处理事项；顶部停止按钮在切换页面后仍然可用。

“手动参与”在弹窗中填写直播间地址和可选备注，先验证后参与，遵循相同的预算、休息及风险规则。失败保留输入；验证中可以取消验证并停止。存在风险或未决支付时先到记录页处理。

自动与手动任务互斥，正式参与保持一个房间。所有工作页面共享登录上下文。关闭主窗口会缩到托盘；结束程序请使用托盘“退出”。计划休息只在应用仍运行时恢复，不创建系统定时任务，不自动开机启动。

直播间福袋里的“手动参与”属于正常参与步骤。程序会先完成已识别的评论、关注或允许的粉丝团任务，再确认参与成功；要求分享或转发直播间的福袋直接跳过。粉丝团要求仍受付费策略和全部预算限制，并非只要有余额就为新主播开团。

“首页重复扫描间隔”只约束重新扫描入口页，队列中的房间按导航间隔逐个验证。临近开奖且来得及时会接管当前页面；距离开奖较远的房间先保留预约，到时复验并参与，不会仅因等待超过 5 分钟消失。小时额度耗尽时，运行面板会说明等待原因。

## 选择与复用

- 机会目标：在名额与福袋参与人数可得时估算机会/时间；否则显示概率未知，按任务和时间排序。
- 钻石目标：还需明确奖品数量，扣除本轮新增钻石成本；不是现金收益。
- 实物相关选项暂不可用：当前电脑端不支持需要手机 App 参与的超级福袋，“全部”仅包含已支持类型。
- 优先复用：每轮按资格、时间和预算判断，首次发现也可在限制内付费，不要求两次发现。
- 仅已有资格：任何新增粉丝团费用均跳过。
- 仅历史许可模式：保留原有许可范围，仍需通过全部额度检查；当前房间库不提供逐房付费许可编辑。

房间按最近发现展示，复访由策略判断，屏蔽阻止后续选择。历史加入粉丝团不等于当前有效，系统每轮重新检查。连续参与默认最多 6 轮；每次驻留最多 20 分钟；上一轮结束后最多等下一袋 60 秒。一次未中奖不会永久拉黑主播。

## 预算和异常支出

总有效额度 = 基础预算 + min(追加上限, floor(已确认钻石奖励 × 可用比例))。关闭“允许使用已确认钻石奖励”时追加为零。

预留、已提交和待核对都占用额度；支出成功后转为已用。每次付款同时检查总预算、每天支出、主播累计、单次费用、每日新开团数。未知价格不付款；已满足资格且不新增费用时总预算为零仍可参与。

“待核对”表示无法确定实际扣款结果，不代表失败。先查看抖音账单，再在记录面板确认“已扣款”或“未扣款”。确认未扣款才释放预留。不要靠反复启动或重置统计重新支付。

每日额度按配置时区计算，默认 Asia/Shanghai。未决款项跨日仍保留占用；确认付款按确认日保守计入每日支出。重置统计仅改变展示窗口，历史支出和已确认奖励不会消失。

## 运行与休息

| 状态 | 行为 |
| --- | --- |
| 运行中 | 允许发现、验证、进房及当前任务 |
| 等待收尾 | 不接新轮次，等待已开始的一轮；仍受硬截止约束 |
| 计划休息 | 关闭工作页面，不扫描、不验证、不点击 |
| 恢复检查 | 校验账号、允许时段、风险、未决支付和每日活跃额度后开始新时段 |
| 需要处理 | 明确限制或支付异常阻断；处理后解除，仍需手动启动 |
| 已停止 | 不执行页面任务；手动停止取消原定恢复 |

允许开始/结束时间相同表示全天，开始时间晚于结束时间表示跨午夜。允许时段结束、定时停止和每日额度均参与硬截止计算。应用重启、系统时钟跳变或长时间挂起不会补做过期任务。

设置的间隔不是抖音官方“安全阈值”。验证码、95152、明确限流不会在 10 分钟后自动重试，也不自动操作验证码。

## 查看结果

提交未确认不计入参与成功；开奖未出现明确结果显示未知。本人中奖可以稍后补充钻石数量，同一福袋只累计一次。优惠券单列；不知道奖励数量时不增加预算。

房间库展示资格、复访时间与样本；最近决策展示选房原因和估计概率。导出文件仅包含允许的统计字段和房间别名，不包含 Cookie、原始账号标识、房间链接、口令或页面原文。诊断时提供脱敏导出，勿发送 `auth.json`。

房间库支持搜索、参与过/已屏蔽/验证受阻筛选，停止后可修改屏蔽。运行记录分为“参与记录”“支出账本”“选择依据”；未决支付与风险集中在页面上方。重置展示统计需确认，账本不受影响。

运行日志最新置顶，支持关键词搜索、暂停自动滚动和清空显示，最近 500 条日志用于查看本次打开应用后的过程。界面语言可在右上角切换；小窗口会收起侧栏文字，表格区域可独立横向滚动。

## 升级和回退

1. 升级前关闭旧程序。首次启动新版本会保留配置备份；第一次确认登录时将旧支出和房间线索迁移到账本，旧中奖仅作历史参考。
2. 新版本数据在用户数据目录的 `runtime-v2.json`；程序日志启动信息可查看该目录。备份整个目录前先退出程序，避免写入过程中复制。
3. 如需回退，先保存新版本 `config.json` 和 `runtime-v2.json`，再恢复旧版程序及 `config.json.before-runtime-v2.bak`。备份中的支出可能早于升级后的真实支出，必须核对并手动补足旧版累计支出后才能继续运行；不能用回退获得新的预算。
4. 新版账号未知、任务/页面格式不兼容时会保守停止或复验。不要通过删除账本来解决识别问题。

历史交付验证范围见 `DELIVERY.md`，对应版本的测试结果不代表中奖效果或平台兼容性保证。
