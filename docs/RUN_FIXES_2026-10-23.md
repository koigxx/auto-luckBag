# 2026-10-23 实跑反馈修复

本次用户从约 00:02 运行到 00:16。持久化记录显示：首页发现 14 个房间，完成 3 个验证，其中 2 个获得可靠网络倒计时，参与和支出均为 0，没有记录风控事件。两个福袋的验证结果分别剩余约 64 秒和 9 分钟，新增费用均为 0，但包含“手动参与”条件而被拒绝。以下测试使用人工脱敏样例，不保存真实账号、Cookie 或线上响应。

## 参与链路

- 精确识别“手动参与”为正常提交步骤；不将其误判为不支持的任务，也不将它解释为已经参与成功。
- 免费参与、手动参与和关注按钮仍须位于可见的本人福袋弹窗中；支持明确的常见评论按钮。
- 评论口令优先使用结构化字段，兼容明确的口令/评论文本；不把“发表评论”“发送口令”等任务说明当作评论内容。口令未知时跳过。
- 评论先于粉丝团，粉丝团仍检查共享预算、每日/主播/单次上限及当前付费许可，限定在当前弹窗带明确金额的按钮上执行。
- 粉丝团流程代办关注；单独关注需确认资格更新后继续。评论、支付和参与各自等待对应确认，防止重复动作及虚报成功。
- 分享/转发直播间任务继续直接跳过，即使同时含有可处理的评论任务。

## 调度与诊断

- 当前页已打开时，临近开奖按当前页所需任务时间评估并接管。拒绝日志保留实际任务原因，不再由再次导航的时间估算覆盖。
- `scanIntervalSeconds` 只限制首页重复扫描。待验证房间仍串行经过原有 45–65 秒导航间隔及小时额度，不再每验证一次额外等待 180 秒。
- 新房或导航小时额度耗尽时显示等待原因，保留队列；不会因为没有导航额度而把未访问房间加入失败冷却。
- 候选不再因验证超过 5 分钟被直接清除。返回时间包含额外 40 秒复验预留，到时重新验证，使用最新身份、倒计时、费用和任务；可参与时接管同一页面。福袋换轮则重新排期，新增分享或不允许的付费要求则跳过。
- 验证缺少倒计时、异常、直接参与、候选等待和跳过均提供原因；名称缺失时尝试补充页面标题。
- 取消本次临时延迟复查，应用保持停止；没有为回归执行真实评论、关注或付款。

## 回归覆盖

- 64 秒免费福袋接管；9 分钟福袋跨 5 分钟保留并按预约复验。
- 复验发现新一轮、分享要求、付费要求；停止发生在异步验证中。
- 首页扫描与验证节奏分离；小时额度用尽保留队列。
- 本地浏览器拦截所有请求，以被动响应完整模拟“评论 → 粉丝团 → 免费参与”，确认只发一次评论、扣一笔账、统计一次参与。
- 免费/手动参与零预算、单独关注后参与、未知口令/分享/预算不足零点击。

离线测试证明这些样例与边界的处理逻辑，不代表已经验证抖音所有页面变体。再次实跑时可根据明确的跳过原因补充脱敏样例。
