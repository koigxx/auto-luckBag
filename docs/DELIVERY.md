## 主流程回归发现并修复

| 问题 | 修复与回归证据 |
| --- | --- |
| 空闲轮询不断把下次扫描时间向后推，导致后续验证不执行 | 只在确实完成一次调度工作时推进截止时间；`runner.test.ts` 连续推进 40 秒验证扫描后仍会进房验证 |
| 停止时登录检查或自动恢复仍在等待，稍后成功又启动运行 | 运行代次检查覆盖异步返回；停止期间旧返回无效；手动入口也等待旧任务完成收尾 |
| 新福袋响应到达，但页面仍显示上一轮结果或任务 | 任务/结果必须匹配当前弹窗的福袋身份；旧结果不初始化新轮，身份变化时停止尚未完成的旧任务 |
| 看播剩余秒数减少，可能缩短实际等待 | 首次采样建立等待截止，之后递减不能把截止提前；离线页面推进时钟验证 |
| 轮询结果覆盖首次任务耗时，重复中奖通知可能影响累计 | 保留首次确认及任务耗时；同轮结果幂等更新，后续仅补全奖励数量 |
| 本人“恭喜您获得…”不含“中奖”，结果弹窗可能被漏判 | 支持本人领取表述，同时保持聊天/礼物流排除；加入浏览器夹具 |
| 时段结束不在任务准入的硬截止内，或休息期间调钟后自动恢复 | 允许时段边界纳入 hardStopAt；对比墙钟和单调时钟，明显跳变要求手动恢复 |
| 跨日未决支出或后确认扣款可能释放每日额度 | 未决款继续占额；确认日计入每日支出，重复回执不改变确认日 |
| 免费福袋的“资格满足”被误当成粉丝团身份 | `memberKnown` 单独表示身份；老会员再次点亮仍计支出，但不误占新开团次数；未知身份保守计数 |

## 迁移与回退

首次加载前保存 `config.json.before-runtime-v2.bak`。账号第一次绑定时，仅将旧累计支出转成开账支出一次；旧中奖汇总是参考数据，不增加可花预算；旧收藏房间资格为未知。明细写入独立的 `runtime-v2.json`，重启清除活动登录绑定并停止运行；未决支付保持占用，需要核对。

离线测试验证重复绑定/迁移不重复记账、账号隔离、冷却与未决款跨重启保留。Electron 冒烟使用临时配置验证原始备份保留 `diamondUsed=7`、`diamondBudget=10`，并复制还原文件后逐字段核对原值。没有在真实用户资料上执行回退，也没有安装运行旧二进制。

回退前关闭应用，备份整个用户数据目录，保留新账本，依据实际扣款核对升级后新增支出后再恢复配置。**不能只恢复旧备份而丢掉升级后产生的支出，否则旧版本会显示多余预算。** 具体步骤见使用说明。

## 已知边界与后续观测

- 身份以账号 UID 哈希隔离；主播档案按规范化直播间 URL 归并。平台若给同一主播不同房间地址，当前不会通过未公开身份接口合并，不应视作跨别名的主播统一限额。
- 已知结构中缺少名额、参与人数或奖品数量时保留 null；使用在线人数代替参与人数、以少量中奖反推确定胜率均未实现。UI 的 K/N 仅是同资格等概率假设下估计。
- 只有可见倒计时而没有可归属身份/任务的房间可保留为复验线索，但不能自动执行。未知任务、金额、等级、看播剩余时间均跳过。
- 当前解析明确的 `lottery_info`、`/webcast/lottery/right/` 身份与已识别灯牌业务回执；未知二进制 WebSocket 不解码成可靠证据。登录、弹窗选择器和响应结构若发生变化，可能需要补充离线样本后调整。
- 自动结果观察截至开奖后约 25 秒；更晚的真实结果若没有再次获得可归属证据，保持 unknown，不凭等待超时判定未中奖。
- 已实现基础样本平滑、有限人数增长外推和任务时长分位数，但尚无线上误差校准，不把这些启发式视作完成 M8 的数据学习研究。
- 明细能支持后续效率、复用和成本比较；当前没有真实策略 A/B 数据，不报告“中奖率提升百分比”。风险阻断需人工处理后明确解除，不承诺随机节奏能够绕过平台检测。
