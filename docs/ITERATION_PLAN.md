# 迭代优化清单：完整改造基线

整理日期：2026-10-22（Asia/Shanghai）

状态：M0—M7 共 32 项必做任务已实施并完成离线验收；M8 保持可选。交付证据、回归修复及限制见 [DELIVERY.md](DELIVERY.md)。
适用范围：当前 Electron + Vue + TypeScript + Playwright 项目的完整改造。

本次改造要解决三个问题：发现直播间缺少选择依据；新增粉丝团支出难以复用；运行节奏只有局部延迟，缺少全局操作预算、休息及可靠恢复机制。实施顺序为“可信记录 → 预算与资格 → 历史房间复用 → 选房及时间调度 → 分段运行 → 界面与验收”。

## 1. 目标、边界与完成口径

| 目标 | 可观察的结果 |
| --- | --- |
| 提高查找效率 | 降低找到一个可参与福袋所需的新房间访问次数，增加已知房间命中率 |
| 提高资格复用 | 主动复访有历史价值的主播；满足条件时连续参与；减少每轮新增钻石支出 |
| 改善选择依据 | 区分识别置信度与机会价值，依据任务、竞争度、成本和时间解释决策 |
| 控制运行负担 | 全局串行操作、访问与付费总量限制、分段运行、休息及可取消恢复 |
| 保证可核查 | 参与、中奖、支出分别记账；未知结果不伪装成成功或失败 |

完整改造的交付范围为 M0—M7 全部必做项。M8 为数据足够后再开展的增强项，不阻塞本次交付。没有取得参与人数等可选字段时，必须交付明确的“未知降级”路径，不能编造字段，也不应因此让整个项目无法运行。

不以“保证中奖”“保证不触发风控”作为验收目标。官方用户协议限制自动化接入，并允许取消不正当参与活动的资格和奖励；低频、被动监听、随机等待不构成平台授权。相关约束见[抖音用户服务协议第 5.1、7.2 条](https://www.douyin.com/draft/douyin_agreement/douyin_agreement_user.html)（核查版本更新于 2026-02-13）。

### 保留的业务约束

- 福袋类型继续支持全部、实物、钻石及组合；优惠券单列，不计入实物与钻石中奖合计。
- 只使用用户正常访问页面产生的 DOM、WebSocket 和 Network Response；不主动调用、枚举或重放平台后台接口。
- 主候选池仅接受结构化福袋响应的可靠倒计时，或可见 ShortTouch 倒计时；普通页面文本不驱动正式进房。
- 自动参与保持单房串行；浏览器页面共享登录上下文；现有房间容量上限 5 不等于允许自动并发参与 5 个房间。
- 单独要求关注时自动处理，不新增关闭项；粉丝团流程不额外预先关注；评论优先于粉丝团任务。
- 付费按钮限定在福袋弹窗内，不能点击头像旁入口、礼物流或整块容器；分享任务继续跳过并结束本轮流程。
- 全局钻石预算持续生效；零新增付费且资格已满足的福袋不因预算用尽而被排除。
- 用户停止后立即阻止后续操作、取消排队与自动恢复，并关闭发现、验证和监控页面。

| E04 | `discovery-service.ts` / `evaluateFudaiSignals` | 根据整页粉丝团文本推断任务，混淆入口、活动条件和账号未满足条件 |

| E06 | `fudai-service.ts` / `handleParticipated`；`stats-service.ts` / `recordParticipation` | 同一福袋只上报一次，首次参与之后的中奖更新可能被去重挡住 |

| E09 | `auto-runner.ts` / `start`、`stop`；`min-interval-queue.ts` | 启停会清除部分冷却状态；队列等待缺乏取消机制，恢复和重启可能破坏限制 |

## 3. 统一的数据与状态约定

| 实体 | 最少需要记录的内容 |
| --- | --- |
| AccountScope | 当前账号作用域；切换账号时隔离资格、账本、结果和恢复计划，不以昵称作为唯一标识 |
| RoomProfile | 稳定主播标识、规范化 URL、来源、最近观测、开播时段、福袋频率、复访时间、失败原因、黑白名单 |
| MembershipState | 未加入 / 当前任务已满足 / 需额外点亮或等级 / 未知；证据来源及确认时间，区分新开团与再次点亮 |
| LotteryObservation | 账号、主播、直播场次（如可得）、lotteryId、类型、drawAt、任务、名额、参与人数、奖品数量、原始单位与观测时间 |
| Participation | 提交与确认时间、资格证据、任务耗时、结果状态、奖励信息；由同一记录持续更新 |
| BudgetEntry | 预留、提交、确认、失败、待核对；用途、金额、账号、主播、关联福袋和操作标识 |
| RunSession | 状态、开始时间、停止接新任务时间、硬截止、nextResumeAt、累计活跃时长、停止原因和恢复开关 |
| RiskEvent | 信号来源、出现时间、影响范围、证据摘要、暂停原因、是否已处理；不能被重新启动清空 |
| DecisionRecord | 候选快照、可用字段、规则版本、评分组成、选择/跳过/续留原因及随机选择记录 |

字段统一带 `source`、`observedAt`、`confidence`；必要时增加 `expiresAt`。未知用 `null/unknown`，不使用 0 表示“不知道”。直播间在线人数与福袋参与人数分开存储；奖品总额、单人奖励、中奖名额分开存储。

福袋身份优先采用账号作用域 + 稳定主播/直播场次标识 + 平台 lotteryId。缺失 lotteryId 时使用带置信度的临时键；不得仅因倒计时变化创建新一轮，也不得将身份存疑的记录用于重复付款或重复增加奖励。

参与与结果分别建状态，避免“未看到中奖”等价于“未中奖”：

```text
参与：observed → eligible → submitted → confirmed
                         ↘ failed / unknown
结果：pending → won / lost / unknown / cancelled
支付：reserved → submitted → confirmed / failed / unresolved
```

同一轮可以补全结果和钻石数量，统计按状态变化增量更新，不能再次增加参与数。迟到证据可修正 `unknown`；修正与冲突必须留下依据。历史上已经付出的成本用于统计，不能成为未来无限续留的理由。

配置继续由 `electron-store` 保存；明细与持久化状态通过仓储接口访问，具体存储方案在 BASE-02 确定。保留旧聚合数据的来源标记，不能反推不存在的逐轮记录。

### M4：可解释选房与任务时间调度（P1）

| 状态 | ID | 任务 | 交付及验收 | 依赖 |

| [x] | STRAT-04 | 控制探索、切换与随机候选选择 | 只在相近质量候选间随机选择；引入近期去重、探索配额和切换成本；保留随机种子/选择结果供离线复现；随机性不能突破任务截止、冷却或预算；空队列不触发访问风暴 | ROOM-02、STRAT-03 |

初版模型采用明确假设，不宣称还原平台抽奖算法：

```text
在每人一次资格且等概率抽取的假设下：
单轮中奖概率估计 p = min(1, 中奖名额 K / 预计最终有效参与人数 N)
机会效率 = 获得有效资格的概率 q × p / 总占用时间 T
钻石效率 = (q × p × 单次中奖钻石期望值 - 本次新增钻石支出) / T
```

总占用时间包括本次可归属的验证、任务、等待和切换成本，不能重复计费。奖品总额不能误当单人奖励。实物使用偏好或明确的价值区间，不能直接用主播口播价格与钻石金额相加。资格复用主要体现为成本和耗时减少，不直接增加抽签概率。

竞争数据未知时以资格、任务明确度、历史有效机会、额外费用和耗时排序，展示“竞争度未知”。正式候选选择可对最多 5 个候选枚举可行组合；排序的效用/时间启发式与组合的总效用目标应分开，避免盲目相加比率。

## 5. 配置基线与生效规则

下面是已落地的产品初值，用于离线验证和首轮试用评估，并非抖音公布或已验证的“安全阈值”。预算额由用户设置；不能把示例上限视为实际付费授权。

| 配置 | 建议初值 / 规则 |
| --- | --- |
| 选择目标 | 单位时间有效中奖机会；竞争数据不足时自动降级为可解释规则 |
| 粉丝团策略 | 已有资格优先、有限开新团；迁移时不扩大原有预算；支持仅已有资格 |
| 单次运行的新房来源配额 | 已知房间约 80%、探索约 20%；冷启动有限探索，不强行为凑配额访问 |
| 自动正式参与房间数 | 1；候选数据默认 4、最多 5 |
| 单段运行时长 | 25–40 分钟中选一次，收尾必须受每日/用户设置的硬截止约束 |
| 计划休息时长 | 10–20 分钟中选一次，持久化实际恢复时间 |
| 每日累计活跃时间 | 120 分钟；包括扫描、验证、参与与收尾，计划休息不计入 |
| 同房连续参与轮数 | 每次驻留最多 3 轮；以后按复访冷却重新验证 |
| 同房连续驻留时间 | 20 分钟；接新一轮前检查可否在上限内完成 |
| 等待下一轮上限 | 初始 60 秒；获得足够历史后允许在用户上限内调整；超时退出 |
| 未知新房间访问预算 | 滚动 60 分钟内最多 8 个；包含失败访问，不能重启清零 |
| 全部进房约束 | 全局间隔 45–65 秒，每小时最多 20 次导航；历史复访不豁免 |
| 页面动作约束 | 每分钟最多 20 个动作，短延迟后再次检查停止、风险与截止时间 |
| 每日新开团上限 | 2 个，计入预留及已确认；再次点亮仍受支出上限，不能绕过 |
| 支付成本未知 | 不自动付费；结果未决不重复点击、不释放预留 |
| 同一普通任务重试 | 当前采用更保守的单次发送；无确认反馈就结束本轮，不重复评论或付款 |
| 奖励再投入 | 默认关闭；开启后仅已确认奖励，并受用户设定比例和上限限制 |
| 计划休息自动恢复 | 当前已启动计划中可启用；用户手动停止立即取消 |
| 应用重新启动后的恢复 | 默认仅显示待恢复计划，不自动打开房间或发起动作 |
| 验证码/明确限制后恢复 | 保存风险状态，处理并明确恢复后再检查条件，绝不按固定冷却自动重试 |

减少操作量与避免重复付费是可验证目标，不能从这些参数推导“不会触发风控”。官方安全政策披露了账号、设备、网络及操作日志等多类安全判断信息，未公布统一操作频率阈值，见[隐私政策第 1.7 节](https://www.douyin.com/draft/douyin_agreement/douyin_agreement_privacy.html)（2026-09-11 更新）。

## 7. 必须覆盖的验收场景

| 场景 | 通过条件 |
| --- | --- |
| 点击参与但没有确认 | 提交未确认/未知，不增加确认参与数 |
| 同一轮先参与后中奖，重复发送结果，稍后补全金额 | 参与数为 1，中奖数最多 1，奖励累计只含最终确认数量；补全不重复入账 |
| 看不到开奖弹窗 / 结果延迟到达 | 标记 unknown 或 pending，后续证据可更新，不直接计未中奖 |
| 聊天或礼物流显示他人中奖 | 不改变本人结果或可用预算 |
| 总预算为 0，但本轮资格已满足 | 免费参与不被粉丝团文案误拦截 |
| 礼物请求失败、超时、重复响应或中途崩溃 | 不伪报支付成功；未决支出不再次支付；重启可核对且无重复入账 |
| 两个入口同时请求最后一笔预算 | 只有满足原子预留的一笔可执行 |
| 评论后按钮变成粉丝团按钮 | 在当前弹窗继续；不点击头像入口、不误送普通礼物 |
| 不支持的分享、未知等级或无法完成的看播任务 | 有明确跳过原因，无额外付费尝试 |
| WebSocket 文本与可靠网络倒计时同时存在 | 使用允许的可靠证据，旧信号不覆盖新轮身份 |
| 隐藏/视口外福袋入口；页面通用倒计时 | 不触发正式参与，不进入主候选池 |
| 连续两轮不同 lotteryId，旧轮定时器晚到 | 分别结算；旧轮定时器不关闭新轮、不重付已满足资格 |
| 首页不再展示已加入粉丝团的主播 | 独立复访仍可在允许时间调度，不依赖首页命中 |
| 没有中奖名额或参与人数 | 显示未知，采用规则排序，不生成假胜率 |
| 两候选开奖接近但任务耗时不同 | 根据完整占用区间选择可行方案；不会为赶第二轮打断已确认的第一轮 |
| 到休息边界时当前轮未结束 | 不接新任务；收尾受硬截止约束；未获得结果时记待核对并清理页面 |
| 计划休息到期 / 明确风险暂停到期 | 前者通过检查可恢复；后者维持阻断，不自动尝试验证码或受限操作 |
| 运行、队列等待、付费确认等待时点击停止 | 立即阻止后续动作；取消排队和恢复；关闭页面；迟到回调不启动新任务 |
| 休息中手动添加房间，或其他 IPC 请求触发动作 | 不能绕过全局状态；界面说明原因，不隐式恢复 |
| 重启、休眠跨多个恢复时间、系统时钟变化 | 不补做过期任务、不产生操作突发；冷却与账本保留；默认等待恢复操作 |
| 跨日、切换账号、重置展示统计 | 每日计数按时区正确换日；账号数据隔离；全局预算和未决支出不被释放 |
| 旧配置迁移、迁移重复执行、回退 | 有备份，可恢复；不虚构历史结果、不扩大已授权支出、不自动进旧房间 |

验证包括必要的纯逻辑测试、事件回放、浏览器离线页面样本以及 Electron 界面检查。仅文案或静态样式变化不要求机械增加测试。真实平台样本不足时如实记录限制，不把模拟响应当作线上协议已验证。

## 8. 效果指标与增强项

| 指标 | 计算及解释 |
| --- | --- |
| 确认参与效率 | 确认参与轮数 / 活跃小时；另报含休息的计划总小时，避免隐藏休息成本 |
| 发现效率 | 可参与福袋数量 / 实际验证次数；同时报告来源、无效访问与时间成本 |
| 每轮新增成本 | 已确认相关钻石支出 / 确认参与轮数；未决支出另列，不能当作 0 |
| 每次付费的后续复用 | 付费后、同主播无需新增费用的确认参与次数 / 对应确认付费次数；按可比观察窗口计算 |
| 开团有效使用率 | 观察窗口内至少确认参与 2 轮的新开团数 / 同窗口可充分观察的新开团数 |
| 结果覆盖率 | 有明确开奖结果的确认参与轮数 / 到开奖时间的确认参与轮数 |
| 任务失败与风险事件 | 分别按原因、阶段、来源统计；连续未中奖本身不是风控证据 |
| 钻石净增 | 已确认可归属奖励减确认支出；标注统计周期，不能表述为现金利润 |

先比较可确定的执行效率、预算、复用和记录覆盖，再观察中奖结果。不同策略尽量在相近时段、相同活跃时长和支出预算下比较，并报告样本量与未知比例。离线重放无法知道未实际参与福袋的反事实开奖结果，不能由回放宣称真实胜率提升。

钻石不能兑换现金或在用户之间转让交易，见[钻石服务协议](https://sf3-cdn-tos.douyinstatic.com/obj/ies-hotsoon-draft/douyin/36ba590b-4606-410f-b035-bc38f7ef6a50.html)（2026-10-09 更新）。展示中奖数量、到账/可用确认和钻石净增时应保持这些概念分离。
